WDM.code.time_delay_filters.filters.FILTER_TABLE_BLOCK_BYTES = 268435456

Default working-set budget, in bytes, for one frequency block of build_filter_tables. The whole point of the blocking is that the peak allocation stops depending on \(N\), so this only has to be small enough to fit and large enough that the matrix products stay efficient. It is the default of every max_bytes argument in the package, so that the budget has one definition rather than one per call site.

WDM.code.time_delay_filters.filters.build_filter_tables(lags: array, deltas: array, freqs: array, window_FD: array, dT: float, dF: float, df: float, max_bytes: int = 268435456) → array[source]

Evaluate both time-delay filters on a grid of lags and delays.

\(T_{\ell}\) and \(T'_{\ell}\) are the same integral over a different window product, so they are built together. The lag phase and the delay phase separate, which turns the whole grid into two matrix products rather than a loop over \((\ell,\delta)\) pairs.

The frequency axis is the contraction index, so nothing of size \(N\) appears in the result - only in the intermediates. Those intermediates are what used to make this function unusable at year-plus durations: written as a single pair of matrix products they need \(16(3A+B)N\) bytes, which is tens of gigabytes for \(N\sim 10^7\), and it is the choice of num_interp_points (\(B\)) that tips a working configuration over the edge. Two things bound it here:

  • the integral is restricted to the window’s compact support (see window_support), which is exact rather than an approximation and on production grids removes a factor of order \(N_f\);

  • what remains is accumulated over frequency blocks sized by max_bytes, so the peak allocation is capped whatever the grid.

Parameters:

  • lags (jnp.ndarray) – The time index differences \(\ell\), dtype=int, shape=(A,).

  • deltas (jnp.ndarray) – The time delays \(\delta\), shape=(B,).

  • freqs (jnp.ndarray) – The sample frequencies of the wdm object time series.

  • window_FD (jnp.ndarray) – The frequency-domain Meyer window, \(\tilde{\Phi}(f)\).

  • dT (float) – Time resolution of the wdm object.

  • dF (float) – Frequency resolution of the wdm object.

  • df (float) – The frequency resolution of the wdm object time series.

  • max_bytes (int) – Working-set budget, in bytes, for one frequency block. The point of the blocking is that the peak allocation stops depending on \(N\), so this only has to be small enough to fit and large enough that the matrix products stay efficient. Defaults to FILTER_TABLE_BLOCK_BYTES, 256 MiB. Optional.

Returns:

tables – shape=(2, A, B). Index 0 is \(T'_{\ell}\), index 1 is \(T_{\ell}\).

Return type:

jnp.ndarray

WDM.code.time_delay_filters.filters.time_delay_filter_Tl_reference(ell: int, delta: float, freqs: array, window_FD: array, dT: float, df: float) → float[source]

The time-delay filter for the case \(m'=m\) is defined as

(73)\[T_{\ell}(\delta)=\int\mathrm{d}f\exp(2\pi i f(\ell\Delta T-\delta)) |\tilde{\Phi}(f)|^2 .\]

This function is SLOW and is NOT used in production; build_filter_tables builds the same quantity for a whole grid of lags and delays at once. It is kept as the reference implementation of the defining integral, against which the tabulated version is tested.

  • window_FD (jnp.ndarray) – The frequency-domain Meyer window function, \(\tilde{\Phi}(f)\) of the wdm object.

  • dT (float) – Time resolution of the the wdm object.

  • df (float) – The frequency resolution of the wdm object time series.

WDM.code.time_delay_filters.filters.window_support(window_FD: array, shift: int) → tuple[source]

Bound the frequency samples that can contribute to the filter integrals.

The Meyer window is compactly supported: window_FD is exactly zero outside a band of roughly \((1-A_{\rm frac})N_t\) samples centred on \(f=0\), which on production grids is a factor \(\sim N_f\) shorter than the array itself.

The range is measured from the two window products themselves rather than inferred from the support of window_FD. Inferring it needs the argument that each factor of the rolled product is the same support translated by \(\mp\) shift, so the product lives on the overlap of the two translates, which sits inside the untranslated support. That argument holds only while neither translate wraps: jnp.roll is circular, so a copy pushed off one end reappears at the other, and the overlap can then land somewhere the untranslated support does not cover at all. Trimming to the window’s own support would silently integrate over the wrong samples. Measuring cannot make that mistake, and costs one boolean array of length \(N\).

The masks are exact: a product of two floats is non-zero wherever both factors are, so the only discrepancy possible is a product underflowing to zero where the mask says otherwise, which widens the range rather than narrowing it.

Parameters:

  • window_FD (jnp.ndarray) – The frequency-domain Meyer window, \(\tilde{\Phi}(f)\), shape=(N,).

  • shift (int) – The half-bin index offset \(\Delta F/2\delta f\) applied to the window in the \(T'_{\ell}\) integrand.

Returns:

start, stop – Half-open index range covering every sample at which either window product is non-zero. (0, N) is returned if neither is ever non-zero, and also whenever the non-zero samples straddle the array edge, so the caller always integrates over a superset of the true support.

Return type:

int
